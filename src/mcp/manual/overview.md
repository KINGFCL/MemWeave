# MemWeave 总览：这是你的长期记忆

这是你的长期记忆，不是搜索引擎。这里没有相似度检索，也没有关键词索引。能不能想起一件事，靠你自己从目录出发沿关联走图，读完节点后自己判断。

这份说明书告诉你系统是怎么工作的，以及遇到各种情况该怎么做。规则是定好的，照做，不用自己重新设计。示例里的 `ownership`、`borrowing` 等节点只是演示用的，你的记忆里不一定有。

## 记忆长什么样

**节点**是一条知识，你能控制的只有五项：

| 字段 | 含义 |
| --- | --- |
| `id` | 节点地址，创建后不能改 |
| `title` | 标题，一眼看出在讲什么 |
| `desc` | 你的理解，是记忆的主体 |
| 证据 | 你凭什么知道：来自哪段原文，或者由哪些节点推出 |
| `related` | 读到这里，还该接着看什么 |

**有两种关系，互不相干：**

- `related` 管导航，决定这条知识找不找得到。它是单向的。你希望反过来也能走到，就自己再 `link` 一次。
- `based_on` 管逻辑，决定这个结论是否还站得住。

所以还有结论依据的节点不能删，而关联断了只是可能找不到。

**总表是目录，不是索引。** 它按知识领域分成板块，每个板块有名字、描述和几个代表节点，其他节点都靠 `related` 到达。代表只是入口：它本身答不了问题，不代表这个领域没有答案。

**原文不可变，记忆可以改。** 原文按内容哈希存放，存进去就改不了。你的理解错了就改描述；原文错了或过时了，就存一段新原文，让节点改为引用它。

**证据是你推理的依据。** 描述是你当时的理解，可能有错。重要结论不要只看描述，要用 `evidence` 沿着依据一路追到原文。

**总表也是你的工作台。** 上面除了知识的领域，还有工作板：目标、步骤和做到哪了，以及最近做过什么。每次工具调用的结果都附带这些内容，由你主动维护，见 `work`。

**时间由系统记录。** 每次修改都进时间线，节点也有创建和更新时间。你改不了，所以能用来判断新旧。

## 底层原理

- 图常驻内存，由 C++ 实现。节点之间用内存地址相连，沿关联走一跳是纳秒级，所以走图很便宜，不用为了省步数而少看。
- 你只接触文本地址，碰不到内存地址。地址写错或节点已删除，只会得到报错，不会崩溃。
- `related_by` 和 `based_by` 这两个反向列表由系统维护，你不用管，也改不了。需要时可以查询它们。
- 这张图只属于一个进程。其他 agent 要用，就用 `export` 导出一份给它，各用各的。

## 脚本怎么执行

你用脚本操作记忆，脚本像代码一样先编译检查再运行：

1. 检查语法，再按顺序模拟每条语句的效果。后面的语句能看到前面语句的结果。
2. 有错就一次报告所有错误，**整段都不执行**，图、日志和原文都不变。
3. 全部通过后，依次存入新原文、把脚本写入日志并落盘、修改内存里的图。
4. 下次启动时读快照并重放日志，所以修改不会丢，崩溃也能恢复。

一段脚本要么全部生效，要么完全不生效。需要几步一起成功的修改，就写在同一段脚本里。没有撤销指令，要恢复就写新的修改。

## 工具

- `memory_read(script)`：只读。查询都用它。
- `memory_write(script)`：可以修改记忆和导出。修改都用它。
- `memory_manual(topic)`：读这份说明书。

## 接下来读什么

第一次使用，读完这里后继续读 `recall`、`write` 和 `work`。其他主题在用到时读。

| 主题 | 什么时候读 |
| --- | --- |
| `recall` | 要回忆、回答可能用到过往知识的问题 |
| `write` | 要记下新知识 |
| `work` | 要开始工作、拆步骤、记录进度、看时间线、记下经验 |
| `repair` | 要纠正、处理矛盾、删除、修复 `check` 的问题、导出 |
| `language` | 要查指令的完整写法 |
| `errors` | 脚本报错，不知道怎么处理 |
