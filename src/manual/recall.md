# 回忆：怎么从记忆里查到东西

**查什么、怎么查、查到什么时候为止，都由你决定。** 系统不替你挑选，也不替你判断够不够。下面是默认的走法和遇到各种情况的处理方式，不是限制。

什么时候查记忆，由接入你的 agent 决定，按系统提示和用户的要求做；没有要求时你自己判断。决定查了，就不要为了省 token 或时间少看：够不够，只看你能不能把问题答好。

## 默认的走法

**第一步：先看你手里有什么。** 工作板上的目标和当前步骤、最近行为、你已经知道地址的节点。已经知道地址，就直接 `revision show`。一次查询开始时，用 `revision catalog show` 看一次总表和工作板就够了，查询中间不会重复出现。

```memweave
revision catalog show
```

**第二步：带着这些信息看总表，选入口。** 根据每个板块的描述，判断哪些领域可能相关，从它们的代表节点开始。代表只是入口，它本身答不了问题，不代表这个领域没有答案。拿不准就多选。

想查一个词但不知道地址时，也是这样：想想它属于哪个领域，从总表进入。这里没有搜索，也不需要搜索。

**第三步：一层一层读。** 同一层想看的节点写在一段脚本里。`revision show` 会显示节点的全部内容。

```memweave
revision show ownership, borrowing
```

**第四步：判断，再决定往哪走。** 内容有用就留下。本身没用，但它的 `related` 可能通向有用的知识，也可以接着走，它是桥梁。

```memweave
revision show drop, send-sync
```

**第五步：回头看总表。** 读到的新内容可能说明另一个领域也相关，比如查 `Rc` 时读到跨线程，就可以回头从并发的领域进入。

**第六步：你觉得信息够了，就停下来自己推理。** 不要求走完整张图。还不够，就继续查。

**依据要紧时，追到原文。** 描述是当时的理解，可能有错。`revision evidence` 会沿依据一路追到原文，列出依据节点的标题和描述，以及所有原文。

```memweave
revision evidence send-sync
```

**查的时候可能有发现。** 两条信息有关系可以 `link`，几条信息能得出新结论可以 `add`，依据写清楚。要不要主动加和怎么加，见 `manual-write`。
