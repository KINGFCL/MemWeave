# 工作板：把总表当成你的工作台

第一次工具调用和总表、工作板变化时，结果会附带它们，要再看一遍就用 `catalog show`，所以你能知道在做什么、做过什么、记忆里有什么。系统只记录，不替你判断。要不要用工作板、什么时候看，由接入你的 agent 决定，按系统提示和用户的要求做。

工作板写进磁盘。对话结束、进程重启后，下一个你能接着做。用了工作板就要当场更新，过时比没有更糟。

## 用工作板时怎么做

| 情况 | 怎么做 |
| --- | --- |
| 想知道有没有没做完的目标 | 看 `catalog show` 里的工作板。有的话可以接着做，或者问用户要不要接着做 |
| 工作板上有进行中的步骤 | 这是上次做到的地方。已经 `[x]` 的步骤不要重做 |
| 要跟踪一个多步任务 | 先 `goal create` 拆好步骤，再动手 |
| 一步做完 | 当场 `step done`，下一步自动开始。不要攒到最后一起写 |
| 想先做别的步骤 | `step start` 切过去，原来进行中的回到未开始 |
| 卡住了，比如等用户确认 | `step block` 写清卡在哪里，然后告诉用户 |
| 发现要多做一步，或者有一步不用做了 | `step add` 或 `step remove`，编号不会变 |
| 要记下记忆之外的操作，比如改文件、跑测试 | `log` 记下做了什么和结果 |
| 用户改了方向 | 改步骤，或者 `goal drop` 写明原因 |
| 全部做完 | `goal done` 写结果。学到了有价值的东西，可以写成经验节点 |

只需要一步的小事不用建目标。

## 工作板长什么样

```text
工作板
goal publish-mcp "发布 MCP 版本"
  desc: "把 MCP 服务发布到 crates.io，做到别人能安装并连接。"
  [x] 1 "跑完回归"
  [>] 2 "升级版本号"
  [ ] 3 "发布"
  [!] 4 "写公告" 卡住：等用户确认
最近行为
  2026-10-31T11:52Z step done publish-mcp 1
总表
section "MemWeave 的实现"
  desc: "..."
  no-memory-pool "节点用 new 分配，不做内存池"
```

`[x]` 已完成，`[>]` 进行中，`[ ]` 没开始，`[!]` 卡住。目标结束后离开工作板，留在时间线上。
